# Mesto Tours App (Modular Monolith)

Это полностековое приложение для бронирования туров, реализующее классическую архитектуру **Modular Monolith** (Модульный Монолит). 

Приложение спроектировано с четким разделением на бизнес-модули (Bounded Contexts), что делает его идеальным кандидатом для изучения паттернов миграции на микросервисную архитектуру.

## Архитектура проекта

Проект использует **Client-Server** архитектуру:

### 1. Backend (Python + FastAPI)
Бэкенд представляет собой модульный монолит, который общается с единой разделяемой реляционной базой данных (Shared Relational Database на базе **SQLite**).
*   Код разделен на 3 независимых домена (модуля) внутри папки `backend/modules/`:
    *   **Auth (Identity):** Регистрация, авторизация (JWT), профили пользователей, роли.
    *   **Catalog:** Управление турами (CRUD для администраторов, просмотр для клиентов).
    *   **Booking:** Корзина, избранное, оформление заказов (Checkout). В монолитной архитектуре делает жесткие SQL `JOIN`-запросы к таблице туров из каталога.

### 2. Frontend (React + TypeScript)
Single Page Application (SPA), общающееся с бэкендом по REST API.
*   **Стек:** Vite, React, TypeScript, React Router.
*   **Стейт-менеджмент:** Zustand (разделен на `useAuthStore` и `useTourStore`).
*   **Архитектура:** Изолированные компоненты, страницы (`pages`) и UI-кит (`ui`).
*   **Продакшн:** Собирается и отдается через **Nginx** (настроен fallback на `index.html` для роутинга).

## 🚀 Быстрый запуск (Docker Compose)

Проект полностью Docker-изирован. Для запуска вам понадобится только установленный **Docker** и **Docker Compose**.

1. Клонируйте репозиторий и перейдите в корень проекта.
2. Выполните команду для сборки и запуска контейнеров:

```bash
docker-compose up --build -d
```

3. После успешной сборки:
   * **Frontend (Приложение):** [http://localhost](http://localhost)
   * **Backend API (Swagger Docs):** [http://localhost:8000/docs](http://localhost:8000/docs)

*(Все данные сохраняются в файл `mesto.db` в папке бэкенда и не пропадают при перезапуске)*

## 👥 Роли пользователей

В системе есть 3 уровня доступа:
1. **Гость** — может только просматривать каталог туров.
2. **Пользователь** — может добавлять туры в корзину, избранное, оформлять заказы и редактировать свой профиль.
3. **Администратор** — имеет доступ к скрытой панели управления, откуда может добавлять и удалять туры.
   - *Тестовый аккаунт администратора:* `admin@mesto.com` / `admin`

## 📦 Структура директорий

```
Mesto/
├── backend/                  # Монолитный Backend (FastAPI)
│   ├── modules/
│   │   ├── auth/             # Bounded Context: Аутентификация
│   │   ├── catalog/          # Bounded Context: Каталог
│   │   └── booking/          # Bounded Context: Корзина и Заказы
│   ├── database.py           # Настройка SQLite
│   ├── main.py               # Точка входа FastAPI
│   └── Dockerfile            # Сборка бэкенда
├── src/                      # Frontend (React)
│   ├── api/                  # Настройка fetch HTTP-клиента
│   ├── pages/                # Страницы приложения
│   ├── store/                # Zustand сторы
│   ├── ui/                   # Переиспользуемые UI компоненты (кнопки, инпуты)
│   └── widgets/              # Крупные блоки (Header)
├── Dockerfile                # Сборка фронтенда (Vite build -> Nginx)
└── docker-compose.yml        # Оркестрация контейнеров
```
